# OmniMind Studio 测试界面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立类似 LangSmith Studio 的 React 测试界面，支持对话、流程开关、私有知识库管理和复习通知。

**Architecture:** 使用 LangChain v1 React stream SDK 连接 Agent，同时使用类型化 REST client 管理知识库、计划和通知。`user_id` 切换通过 generation token 隔离旧请求。

**Tech Stack:** React 19、TypeScript、Vite、`@langchain/react`、TanStack Query、Vitest、Testing Library、Playwright。

## Global Constraints

- 三栏布局：左侧导航、中间聊天、右侧流程检查器。
- Agent 流程开关默认关闭，只影响渲染，不影响执行和服务端事件。
- 测试 UI 默认普通模式：只允许选择和检索当前 `user_id` 的知识库；创建、上传、重试、重命名和删除只在管理员模式渲染。
- 管理员模式是测试 UI 功能开关，不是真实鉴权边界；首版整体仍由 Caddy 测试访问保护，后续接入认证时由服务端角色替代。
- 不展示隐藏思维链；只展示 Agent、工具、检索、摄取和错误结构化事件。
- `user_id` 变化时中止请求并清空所有用户缓存。
- 前端不得包含 DeepSeek、Qwen、RAGFlow、MongoDB 或 MinIO 服务端密钥。
- UI 文案与提交信息使用中文。

```typescript
// web/src/features/inspector/eventReducer.ts
import type { AgentEvent } from "../../api/types";

export type InspectorItem = { key: string; label: string; status: "running" | "done" | "failed"; detail?: string };

export function reduceEvent(items: InspectorItem[], event: AgentEvent): InspectorItem[] {
  if (event.type === "agent.started") return [...items, { key: `${event.agent}-${items.length}`, label: event.agent, status: "running", detail: event.task }];
  if (event.type === "tool.started") return [...items, { key: `${event.name}-${items.length}`, label: event.name, status: "running", detail: event.summary }];
  if (event.type === "tool.failed") return [...items, { key: `${event.name}-${items.length}`, label: event.name, status: "failed", detail: event.error }];
  return items;
}
```

- [ ] **Step 1: 写旧请求不能污染新用户测试**

```tsx
it("切换用户后递增 generation 并清空 thread", () => {
  const { result } = renderHook(() => useUserSession(), { wrapper: UserSessionProvider });
  act(() => result.current.setUserId("u1"));
  const first = result.current.generation;
  act(() => result.current.setUserId("u2"));
  expect(result.current.generation).toBe(first + 1);
  expect(result.current.threadId).toBeNull();
});
```

- [ ] **Step 2: 实现 generation token**

Provider 状态固定为 `{userId, mode, threadId, generation, signal}`，`mode` 初始为 `user`。`setUserId(next)` 先校验 `^[A-Za-z0-9_-]{1,64}$`，再调用当前 `AbortController.abort()`、创建新 controller、递增 generation、把 mode 重置为 `user`、清空 thread/messages/mounted knowledge bases，并执行 `queryClient.removeQueries({queryKey: ["user", oldUserId]})`。所有 API 方法捕获调用开始时的 generation，响应完成后只有与当前 generation 相等才能写状态；测试用两个可控 Promise 让旧用户响应后完成，断言 UI 中不出现旧数据。

- [ ] **Step 3: 实现通知动作**
